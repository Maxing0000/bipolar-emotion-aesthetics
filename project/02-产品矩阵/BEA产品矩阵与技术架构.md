## 二、产品一：BEA Agent Skill

### 2.1 产品定位

封装为标准 AI Agent 技能，供 AI 助手（如豆包、ChatGPT 等）调用，提供专业的美学分析、诊断和设计建议能力。

### 2.2 功能特性

| 功能 | 说明 |
|---|---|
| **理论查询** | 回答 BEA 理论相关问题，提供概念定义、范式说明、方法论指导 |
| **范式定位** | 根据用户描述的设计需求，推荐合适的 BEA 范式 |
| **W(T) 计算** | 输入各维度危极强度，计算整体危极权重 W(T) |
| **极性审计** | 分析设计方案的各维度极性方向和强度 |
| **病症诊断** | 识别常见审美病症（甜腻症、攻击症、均分症等） |
| **设计处方** | 给出元素级可执行的改进建议 |
| **分领域配方** | 提供消费电子、汽车、建筑、品牌、界面等领域的设计配方 |

### 2.3 文件结构

```
bipolar-emotion-aesthetics/
├── SKILL.md                          # 技能入口（触发条件、核心命题、安全合规）
├── references/
│   ├── theory.md                     # 理论基础（本体/机制/元素/结构/阈值）
│   ├── paradigms.md                  # 范式谱系与语境调制
│   ├── method.md                     # 创作方法论（六步法/配比算法/评分卡）
│   ├── playbooks.md                  # 分领域配方与病症诊断处方
│   └── audit-templates.md            # 可复制工作模板
└── scripts/
    ├── wt_calc.py                    # W(T) 计算器 v1.0
    ├── bea_quant_v2.py               # 量化模型 v2.0
    └── bea_quant_v3.py               # 量化模型 v3.0（元素交互效应+非线性权重）
```

### 2.4 触发场景

当用户需要以下操作时触发：
- 分析、评价、诊断或设计任何以感官形式呈现的对象
- 讨论圆润与尖锐、柔和与硬朗、繁与简、明与暗等美学问题
- 上传产品/设计/海报/建筑/UI 图片进行分析
- 回答「为什么好看/不好看/不协调/有廉价感」
- 做设计美学评审、形态或配色提调

| **完整分析报告** | W(T)、范式定位、四象限、四维评分、病症诊断、优化处方 |

### 4.5 BEA 计算引擎 v2.0

**核心功能**：
1. **W(T) 计算**：多维度加权危极权重
2. **范式定位**：8大范式自动匹配（治愈松弛/亲和精致/诗意朦胧/均衡典雅/崇高震撼/冷峻克制/神秘魅惑/先锋反叛）
3. **四象限定位**：张力×秩序二维定位（黄金区/平庸区/焦虑区/混沌区）
4. **四维评分**：张力/秩序/阈值/语境（各25分，满分100）
5. **病症诊断**：8类常见审美病症识别（甜腻症/空洞症/攻击症/刺激疲劳/均分症/失序症/层级冲突/重点通胀）
6. **优化处方**：元素级可执行改进建议

### 4.6 AI 图像分析

**识别维度**：
1. 形状线条（曲线/锐角/对称/失衡）
2. 色彩色相（暖调/冷色/低饱和/高饱和）
3. 明度对比（柔和过渡/硬明暗交界）
4. 质感肌理（光滑/粗糙/温润/冰冷）
5. 构图空间（居中稳定/偏移裁切/留白/拥挤）
6. 光影（漫射柔光/硬光/长投影）

**输出格式**：结构化 JSON，包含各维度极性方向（P/T）、强度（0-10）、元素描述。

## 五、产品四：跨端小程序（Taro）

### 5.1 产品定位

基于 Taro 框架的跨端小程序，一次开发，支持微信小程序、抖音小程序、H5 三端运行。

### 5.2 为什么选择 Taro

| 方案 | 开发效率 | 多端支持 | 生态成熟度 | 推荐度 |
|---|---|---|---|---|
| **Taro** | 高（一次开发多端运行） | 微信/抖音/支付宝/H5 | 高（京东开源，社区活跃） | ★★★★★ |
| uni-app | 高 | 多端 | 高 | ★★★★ |
| 原生开发 | 低（分别开发） | 单端 | 最高 | ★★★ |

**选择 Taro 的理由**：
1. React 语法，前端开发者上手快
2. 一次开发，编译到微信/抖音/H5 三端
3. 完全复用 H5 MVP 的后端 API，后端零改动
4. 生态成熟，组件丰富，社区支持好

### 5.3 功能特性

| 功能 | 说明 |
|---|---|
| **首页** | BEA 品牌头部、大拍照按钮、拍照/相册快捷入口、最近分析历史、精选案例 |
| **分析中页面** | 原图预览、双环加载动画、5步分析进度、失败重试机制、自动跳转报告页 |
| **报告页** | 报告头部、6张分析卡片、底部操作栏（再拍一张+原生分享） |

| **本地存储** | 跨端存储封装，保存分析历史 |

### 6.2 数据流

```
用户拍照/上传图片
    ↓
前端压缩图片（≤2MB）
    ↓
POST /api/analyze（multipart/form-data）
    ↓
Flask 接收图片，保存到 data/uploads/
    ↓
ai_analyzer.py 调用豆包视觉 API
    ↓
AI 返回 6 维度极性分析（JSON）
    ↓
bea_engine.py 计算 W(T)、范式、四象限、评分、诊断、处方
    ↓
保存分析结果到 data/history/
    ↓
返回完整分析报告（JSON）
    ↓
前端渲染报告（6张卡片 + ECharts 图表）
    ↓
用户可分享、保存到历史
```

## 七、后续技术优化方向

### 7.1 短期优化

1. **ec-canvas 集成** - 小程序端 ECharts 图表（雷达图、散点图）
2. **AI Prompt 优化** - 提升识别准确率，增加更多维度
3. **图片压缩** - 前端压缩图片，减少上传时间和 API 成本
4. **错误处理** - 完善网络错误、API 失败、图片格式错误等处理
5. **加载优化** - 骨架屏、懒加载、缓存策略

### 7.2 中期优化

1. **用户系统** - 注册登录、云端历史同步、个人偏好设置
2. **数据库迁移** - 从 JSON 文件迁移到 SQLite/PostgreSQL
3. **缓存层** - Redis 缓存热门分析结果，减少 API 调用
4. **异步处理** - 图片分析异步化，支持大文件和批量处理
5. **API 网关** - 统一 API 管理、限流、鉴权、监控

### 7.3 长期优化

1. **BEA 专用模型微调** - 基于 BEA 理论和案例库，微调专用多模态模型
2. **开放 API/SDK** - 提供 RESTful API 和各语言 SDK，供第三方集成
3. **实时协作** - 多人实时协作分析、评论、版本管理
4. **边缘计算** - 部分计算下沉到边缘节点，降低延迟
5. **多模态扩展** - 支持音频、视频、3D 模型、AR/VR 内容分析
