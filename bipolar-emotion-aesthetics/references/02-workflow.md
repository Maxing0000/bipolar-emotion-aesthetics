# BEA 工作流与模板

> 本文档回答"BEA 具体怎么用"。所有模板均可直接复制使用。

## 一、设计评审会议流程（45分钟版）

BEA 最常用的场景是设计评审。以下是经过验证的会议流程：

### 会前准备（设计师，10分钟）

1. 准备待评审设计的高清图（正面、侧面、背面、细节）
2. 自己先打一轮 t 值，算出 W(T)
3. 列出你认为最有争议的 1-2 个维度

### 会中流程

| 时间 | 环节 | 操作 |
|---|---|---|
| 0-5min | 独立打分 | 所有参会者对着设计图，按品类维度独立打 t 值，不讨论 |
| 5-15min | 汇总对比 | 收集所有人的打分，计算每个维度的均值和极差 |
| 15-25min | 分歧讨论 | 极差 ≥2 的维度逐个讨论，说证据不说感觉 |
| 25-30min | 计算 W(T) | 用共识值计算 W(T)，定位范式 |
| 30-35min | 病症诊断 | 对照病症表，识别当前设计的问题 |
| 35-45min | 处方与决策 | 给出具体修改方向，确定下一步 |

### 会后输出

一份 BEA 评审记录，包含：
- 各维度共识 t 值与 W(T)
- 范式定位
- 诊断出的病症
- 具体修改处方（哪个维度、调到多少、预期效果）

## 二、竞品分析模板

用于对比多个产品的 BEA 画像，找差异化定位。

### 步骤

1. 选 3-5 个竞品
2. 对每个产品按相同品类维度打 t 值
3. 用 `bea_quant.py compare` 两两对比
4. 画 W(T) 散点图，找市场空白

### 输出表格模板

| 产品 | 形状 | 质感 | 色彩 | 构图 | 光影 | 细节 | W(T) | 范式 | 核心病症 |
|---|---|---|---|---|---|---|---|---|---|
| 产品A | 3 | 6 | 4 | 3 | 5 | 6 | 0.44 | 均衡典雅 | 无 |
| 产品B | 4 | 4 | 4 | 3 | 3 | 5 | 0.39 | 均衡典雅 | 均分症 |
| 产品C | 2 | 3 | 2 | 2 | 2 | 4 | 0.25 | 亲和精致 | 甜腻症 |

### 分析要点

- 如果所有竞品都挤在同一个 W(T) 区间，说明有差异化空间
- 找维度极差最大的产品对，分析是什么造成了差异
- 你的目标产品应该落在哪个区间？为什么？

## 三、设计方向定调流程

新项目开始时，用 BEA 锁定美学方向。

### 步骤

1. **明确受众与场景**：谁用？在哪用？功能风险是什么？
2. **选范式区间**：根据受众阈值和产品定位，选目标 W(T) 区间
   - 大众消费品 → 亲和精致（0.15-0.30）
   - 高端旗舰 → 均衡典雅偏崇高（0.40-0.55）
   - 专业工具 → 冷峻克制（0.60-0.66）
   - 潮牌/先锋 → 先锋反叛（0.66-0.80）
3. **定主辅比**：确定哪些维度是亲极主调，哪些是危极提神点
   - 主调维度（亲极）：占 60%+ 权重
   - 提神维度（危极）：1-2 个维度 t≥6
4. **产出基调卡**：

### 基调卡模板

```
项目：__________
目标范式：__________（W(T) 目标区间：____-____）
主调（亲极）：形状 t=__, 构图 t=__, 色彩 t=__
提神（危极）：质感 t=__, 细节 t=__
约束：阈值安全检查（本能/认知/文化）
参考产品：__________（W(T)=____）
```

## 四、图片分析工作流

当用户上传产品/设计图片时，按以下步骤分析：

1. **视觉识别**：观察图片中的形式元素——形状线条、色彩色相、明度对比、质感肌理、构图空间、光影
2. **极性标注**：为每个维度标注方向（P亲/T危）和强度（0–10）
3. **W(T)计算**：根据品类权重计算整体危极权重，或调用 `bea_quant.py analyze`
4. **范式定位**：对照六范式区间确定风格位置
5. **四维评分**：张力/秩序/阈值/语境各25分
6. **病症诊断**：对照病症表识别问题
7. **改进处方**：给出元素级可执行修改方案（具体维度、目标强度、预期效果）

### 输出骨架

```
1. 情绪基调：第一感受 + 主导范式 + W(T)
2. 双极构成拆解：逐维度方向/强度/作用
3. 定位：范式区间 + 三级阈值检查
4. 评分：四维评分卡总分
5. 核心问题：元素级，按优先级
6. 改进处方：具体维度、目标强度、预期效果
```

## 五、常见误区

### 误区1：把 W(T) 当精确科学指标

**表现**：为了 W(T) 从 0.42 调到 0.43 而争论不休。

**纠正**：W(T) 的误差带至少 ±0.1。0.42 和 0.48 没有本质区别。关注范式区间和维度对比，不要纠结小数点。

### 误区2：所有产品都往"均衡典雅"挤

**表现**：觉得 0.30-0.48 是"安全区"，所有设计都往中间靠。

**纠正**：均衡典雅不是"最好"，只是"最稳妥"。高端旗舰需要崇高震撼的张力，专业工具需要冷峻克制的距离感。根据产品定位选范式，不要默认中间。

### 误区3：用 BEA 替代用户测试

**表现**：W(T) 算出来 0.45，就觉得用户一定会喜欢。

**纠正**：BEA 是设计团队内部的协作工具，不是用户偏好的预测模型。W(T) 高不等于用户喜欢，最终还是要做用户测试。

### 误区4：打分时看别人的结果

**表现**：评审会上大家互相看打分，然后趋同。

**纠正**：必须独立打分后再汇总。BEA 的价值在于暴露分歧，如果大家都趋同，就失去了讨论的基础。

### 误区5：只打分不讨论证据

**表现**：A 说质感 t=6，B 说 t=4，然后投票决定。

**纠正**：分歧 ≥2 时必须说证据。"这个中框是镜面抛光，反射率很高，所以 t=6" vs "这个中框虽然是金属但做了喷砂，所以 t=4"——讨论具体的设计元素，而不是感觉。

### 误区6：忽略语境适配维度

**表现**：只看 W(T) 和病症，不考虑产品给谁用、在哪用。

**纠正**：同样 W(T)=0.55 的设计，放在豪华车上是"崇高震撼"，放在儿童手表上就是"攻击症"。语境适配是四维评分中最需要人工判断的维度。

## 六、命令行速查

```bash
# 分析（JSON输出，适合程序处理）
python3 scripts/bea_quant.py analyze --category phone --t "形状=3,质感=6,色彩=4,构图=3,光影=5,细节=6"

# 完整报告（人类可读）
python3 scripts/bea_quant.py report --category phone --t "形状=3,质感=6,色彩=4,构图=3,光影=5,细节=6"

# 对比两个产品
python3 scripts/bea_quant.py compare --category phone --a "产品A=3,6,4,3,5,6" --b "产品B=4,4,4,3,3,5"

# 生成分打模板
python3 scripts/bea_quant.py template --category phone

# 自测试
python3 scripts/bea_quant.py test
```

支持品类：`phone`（手机/消费电子）、`car`（汽车/交通工具）、`brand`（品牌/平面）、`ui`（界面/交互）
